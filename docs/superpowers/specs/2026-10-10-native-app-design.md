# Native App (macOS / iPadOS) — Design

Date: 2026-10-10
Status: approved for planning (wrapper choice confirmed by the user; the
rest of this document is the proposed design and awaits review)

## Goal

Play Voltopia without a browser: a macOS app (`.app`, shipped as `.dmg`)
and an iPadOS app, both built from the existing web build. The browser
game stays the primary product and is not changed in behaviour; the
native apps are a second distribution of the same `dist/`.

## Decisions

- **Tauri v2** is the wrapper (user decision). Rationale accepted:
  macOS and iPadOS both render in WKWebView anyway; Tauri adds one Rust
  crate (`src-tauri/`) and gives Windows/Linux desktop builds later for
  free. Native Swift + WKWebView and Capacitor were rejected (Swift: no
  reuse beyond Apple; Capacitor: macOS only via Catalyst).
- **One frontend build for web and native.** No separate entry point.
  Native-only behaviour is gated at runtime behind a tiny platform
  module (`src/ui/platform.ts`) and is limited to what WKWebView cannot
  do on its own: file export and save-on-quit.
- **No Service Worker in the native build.** `vite-plugin-pwa` is
  skipped when Tauri drives the build; the app is bundled, offline by
  construction, and a Service Worker inside `tauri://` is only a source
  of stale-asset bugs.
- **iPad only, not iPhone.** The HUD is designed for large screens. The
  Xcode project targets device family iPad (`TARGETED_DEVICE_FAMILY = 2`),
  landscape and portrait.
- **Unsigned/ad-hoc builds first.** Local `.app` and `.dmg`, and an iPad
  build installable on the developer's own device via Xcode. Signing,
  notarization, TestFlight and App Store submission are follow-ups, not
  part of this plan.
- **Bundle identifier** `info.rinne.voltopia` (reverse of the author's
  domain; no `-`, which Tauri rejects on some targets). Change here if
  another domain should own it.

## Architecture

```
Voltopia/
├── src/                       unchanged web app (+ src/ui/platform.ts, one hook)
├── src-tauri/                 Rust shell (new)
│   ├── Cargo.toml
│   ├── build.rs
│   ├── tauri.conf.json        identifier, window, CSP, bundle, build hooks
│   ├── capabilities/default.json
│   ├── icons/                 generated by `pnpm tauri icon`
│   ├── src/main.rs            desktop entry → lib::run()
│   ├── src/lib.rs             Builder, plugins, close-requested handling
│   └── gen/apple/             Xcode project generated by `tauri ios init` (committed)
├── vite.config.ts             Tauri dev-server settings, PWA gated off under Tauri
└── .github/workflows/native.yml  macOS build artefact
```

### Build pipeline

`tauri.conf.json > build`:

- `beforeDevCommand`: `pnpm dev` — Vite on `127.0.0.1:5173`, `strictPort`.
  For a physical iPad the CLI sets `TAURI_DEV_HOST`; Vite then listens
  on that address with HMR on port 1421 (the documented Tauri pattern).
- `beforeBuildCommand`: `pnpm build` — the normal build (`tsc -b && vite build`)
  with `VOLTOPIA_BASE` unset, so `base` is `/`, which is what the
  `tauri://localhost` origin needs.
- `devUrl`: `http://localhost:5173`; `frontendDist`: `../dist`.

Tauri exports `TAURI_ENV_PLATFORM` (and friends) to both hook commands.
`vite.config.ts` reads it: when set, the `VitePWA` plugin is not added.
`envPrefix` becomes `['VITE_', 'TAURI_ENV_*']`; `clearScreen: false`;
`server.watch.ignored` gets `**/src-tauri/**`.

### Rust shell (`src-tauri/src/lib.rs`)

Minimal. Plugins: `tauri-plugin-opener` (external links from the imprint
page and `mailto:` open in the system browser/mail client — the plugin's
init script hooks `target="_blank"` anchors, so no frontend change),
`tauri-plugin-dialog` and `tauri-plugin-fs` (save export, see below).
Desktop only: a `CloseRequested` window-event handler that prevents the
close, emits `close-requested` to the webview, and a `close_app` command
that exits the process when the frontend says it is done. Mobile entry
via `#[cfg_attr(mobile, tauri::mobile_entry_point)]`.

### Capabilities (`src-tauri/capabilities/default.json`)

`core:default`, `core:event:allow-listen`, `opener:default`,
`dialog:allow-save`, `fs:allow-write-text-file` scoped to `$DOWNLOAD/*`
and `$DOCUMENT/*` (the dialog returns a user-picked path; Tauri's fs
scope must still allow it, and the dialog plugin adds picked paths to
the scope at runtime). Nothing else is exposed to the webview.

### Content Security Policy

```
default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline';
img-src 'self' data: blob:; font-src 'self'; worker-src 'self' blob:;
connect-src 'self' ipc: http://ipc.localhost
```

`'unsafe-inline'` for styles is required by React inline styles and the
three.js canvas sizing. The sim worker is a Vite-emitted module file
(`new Worker(new URL('../sim/worker.ts', import.meta.url))`), so
`worker-src 'self'` covers it; `blob:` is a safety net for three.js
texture uploads. The CSP applies only to the Tauri build; the web build
keeps whatever GitHub Pages serves (none).

### Window (macOS)

Title "Voltopia", 1280×800 default, minimum 960×600, resizable, native
title bar, `fullscreen: false`. The game already handles resize via its
ResizeObserver; nothing changes in `src/render`.

### Platform module (`src/ui/platform.ts`)

```ts
export const isNativeApp = (): boolean =>
  typeof window !== 'undefined' && '__TAURI_INTERNALS__' in window;

/** Save `text` under `fileName`: browser download, or a native save dialog. */
export async function exportTextFile(fileName: string, text: string): Promise<void>;
```

`exportTextFile` keeps the current anchor-download path in the browser.
In Tauri, anchor downloads are a no-op in WKWebView, so it calls
`@tauri-apps/plugin-dialog` `save({ defaultPath: fileName })` and, if a
path comes back, `@tauri-apps/plugin-fs` `writeTextFile(path, text)`.
The Tauri imports are dynamic (`await import(...)`) so the browser
bundle does not pay for them and tests can stub them. `SettingsPage`
export switches to this helper; import (`<input type="file">`) works in
WKWebView unchanged.

### Save on quit (desktop)

Today the app autosaves on an interval and on `visibilitychange` →
`hidden`. Cmd+Q on macOS tears the webview down without a reliable
`visibilitychange`. New module `src/ui/nativeClose.ts` with a pure,
testable `createCloseHandler(deps)` and `listenForNativeClose(deps)`,
wired from the existing autosave effect in `App.tsx`:

1. If `isNativeApp()`, `listen('close-requested', …)` from
   `@tauri-apps/api/event` (dynamic import); otherwise a no-op.
2. On the event: `send({ type: 'requestSave' })`, wait for the next
   `onSaveData` callback and for `storage.save()` to settle, then
   `invoke('close_app')`. A 2 s timeout invokes `close_app` regardless,
   so a stuck worker can never make the app unquittable. A second close
   request while one is pending is ignored.
3. The effect depends on `send`/`onSaveData` identities only (CLAUDE.md).

On iPadOS the app is suspended rather than quit; `visibilitychange`
fires on backgrounding in WKWebView, so the existing handler covers it.

### iPad presentation

- `index.html` viewport: `width=device-width, initial-scale=1, viewport-fit=cover, maximum-scale=1, user-scalable=no`
  (double-tap and pinch already go to the canvas; this stops WebKit from
  zooming the page instead of the map).
- `app.css`: `html { overscroll-behavior: none; -webkit-touch-callout: none; }`
  and `padding` on the HUD root from `env(safe-area-inset-*)` so islands
  clear the rounded corners and the home indicator.
- Input already uses Pointer Events with pinch-zoom (`src/render/renderer.ts`),
  so no input work is expected; the manual checklist verifies it.
- Keyboard shortcuts work with a hardware keyboard; no on-screen
  substitute is added (tools are reachable from the toolbar).

### Storage

IndexedDB in WKWebView persists per app and is not subject to Safari's
7-day ITP eviction. Save games therefore live where they live today;
`SaveStorage` is untouched. Export/import is the migration path between
browser and app.

### CI

New `.github/workflows/native.yml` on `macos-latest`, triggered by
`workflow_dispatch` and pushes of `v*` tags (not on every PR — a Rust
build costs minutes): install pnpm, Node 22, stable Rust with
`rust-cache`, `pnpm install --frozen-lockfile`, `pnpm tauri build --bundles app,dmg`,
upload `src-tauri/target/release/bundle/**` as an artefact. The iOS
build needs a signing identity and is not run in CI in this plan.
`ci.yml` is unchanged except that `pnpm lint`/`format:check` now also see
the JSON under `src-tauri/`.

## Out of scope / follow-ups

- Developer ID signing and notarization for the `.dmg`; App Store /
  TestFlight (needs `bundle.macOS.entitlements`, `bundle.iOS.developmentTeam`,
  `tauri ios build --export-method app-store-connect`).
- Auto-update (`tauri-plugin-updater`) — not allowed on the App Store,
  only useful for direct downloads.
- Windows/Linux desktop bundles (Tauri gives them nearly free; needs a
  CI matrix and a check that the Linux WebKitGTK WebGL path is fine).
- Game Center, iCloud save sync, touch-specific HUD.

## Testing

- Unit (`vitest`, node): `platform.test.ts` — `isNativeApp()` false in
  node, true with `__TAURI_INTERNALS__` stubbed on a fake `window`;
  `exportTextFile` picks the browser path vs. the native path (dialog and
  fs modules injected); cancelled dialog writes nothing.
  `nativeClose.test.ts` — `createCloseHandler` with a fake bridge: save
  requested on event, `close_app` invoked after the save settles (also
  when persisting fails), invoked after the timeout when no save
  arrives, second request while pending ignored.
- Existing suites unchanged; `pnpm coverage` thresholds only cover
  `src/sim` and `src/shared`, which this work does not touch.
- Manual on the Mac (recorded as a checklist in the plan): `pnpm tauri dev`
  renders the 3D view, the sim ticks, roads drag, Cmd+S saves, Cmd+Q
  saves then quits, export opens a save dialog, imprint link opens the
  browser; `pnpm tauri build` produces `.app` and `.dmg` that launch;
  `pnpm tauri ios dev` on an iPad simulator and a device: pinch zoom,
  two-finger rotate not required, HUD inside safe area, background then
  foreground keeps the city, reopen after a kill restores the autosave.
- `scripts/smoke.mjs`, e2e and the deploy workflow are unaffected.
